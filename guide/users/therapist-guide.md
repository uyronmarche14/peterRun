# Therapist Guide

For the clinician or supervisor running a PETER RUN session. The game is designed to be **supervised**: you choose the plan, the patient performs it, and you review the outcome together.

## Before the session

1. Start the game. The opening screen shows **Start Session**, **Tutorial**, **Settings** and **Quit**.
2. Optional: open **Settings → Check controller** to confirm the keyboard or controller works (see [Controls](controls.md)).
3. Optional: run the **Tutorial** so the patient can try each movement first.

## Setting up a session

Choose **Start Session**. The *Set up this session* screen has:

| Setting | What it does |
| --- | --- |
| **Route** | Currently **Barangay Morning**. |
| **Repetitions per movement** | Use the **−** / **+** buttons. 1 to 15 for each of Move Left, Move Right, Jump and Slide. Default is 10 each (so 40 total). Range is 4–60 total. |
| **Test controls / Practice movements** | Optional extras before starting. |

Press **Review session** to continue.

## The Ready screen

*"Ready when you are."* It restates the plan. From here you can:

- **Test controls** or **Practice movements** again.
- **Edit session** to go back and change the plan.
- **Start Session** when the patient is ready. A **3, 2, 1, Go!** countdown plays first (about 4 seconds, with no input accepted) so the patient can settle before the first prompt.

Nothing starts until you press Start.

## During the session

- The patient sees one prompt at a time. Each takes about **5 seconds** (about 2½ s to get ready, 2 s to respond, under 1 s to settle).
- **Response time never changes.** The only thing that varies the load is how many repetitions you set. The player can choose faster or slower scenery for the next run on the review screen.
- **Pause** (`P` or the on-screen button) freezes the game at once. From the pause screen you can resume, **End Level**, or **End Session**. Ending asks for confirmation and carries **no penalty**.
- The patient's repetitions count only when they do the **correct** movement in the **correct lane**. Wrong or missing responses are recorded as *neutral misses*. They are not scored against the patient, and the next obstacle is made easier.

### What ends a run

| Reason | What the patient sees |
| --- | --- |
| All planned repetitions done | "Level complete" |
| Peter reaches an obstacle (contact) | "Run ended. Peter reached an obstacle. Completed repetitions are saved for review." |
| You end the level or session | "Level ended" / "Session ended" |

Contact ending the run is intentional. There are no lives, health, score loss or chase. Completed repetitions are always kept.

## Reading the review

The *Session review* screen shows:

- **Completed / planned** for each movement (for example, *Jump: 8 / 10*).
- **Game speed (1–10)**: chosen at the end of a run. 1 = faster scenery, 10 = slower; it applies to the next run (Retry).

Then choose together:

| Button | Meaning |
| --- | --- |
| **Rest** | Pause the decision. Nothing starts automatically. Rest as long as needed. |
| **Retry** | Same plan again. Available **only after a speed (1-10) has been chosen**. |
| **Finish** / **Finish without choosing** | Return to the opening screen. |

## Settings that may help

Under **Settings**: music on/off and volume, route pace, contact effects intensity, and **Reduced motion**. These last only for the current run of the application.

## Good to know

- The game does not diagnose or measure clinical angles. It records what the patient did against the plan you set.
- Review results are held while the app runs. Note anything you need to keep in your own records before closing the game.
- The MOVE wearable, when used, sends the same keys as a keyboard. See [Controls](controls.md).
- PETER RUN is a supervised practice aid, not a medical device. Clinical use and any safety limits remain your professional judgement.
